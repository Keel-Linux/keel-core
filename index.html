Appliances / Keel Core

Keel Core

Debian 13

Keel release 19.0-13 · image debian-13-keel-core_19.0-13_amd64.tar.zst

This is the core appliance of Keel Linux: the base system every other Keel appliance is layered on, compatible with TurnKey Linux appliances. It is a fork of turnkeylinux-apps/core with its full history; upstream is kept as the remote upstream and this repository tracks its master. The recipe (Makefile, plan/main, conf.d, overlay) builds the same image as upstream, as checked by the M0 gate of the project, and the project's own changes are kept small and reviewable on top of it.

Install

LXC template, for Proxmox VE

debian-13-keel-core_19.0-13_amd64.tar.zst

sha256 e32029debdf15a852084a08f24d8187dd526bd3ceebc3cc1e6512a1bf7fb4401

With the Keel index

keel-pve gets the signed index of the Keel templates and checks the template against it. The Templates dialog of the Proxmox web interface does not show Keel templates. Install keel-pve from the Keel archive, suite trixie-testing, as its README says. Then run these commands on the Proxmox node:

keel-pve update
keel-pve download local keel-core

With the file

  1. Download the template, its .sha512 and its .sha512.asc.
  2. Check the signature. Then check the digest.
  3. Copy the template to /var/lib/vz/template/cache/ on the Proxmox node.
curl -fLO https://mirror.keellinux.org/images/debian-13-keel-core_19.0-13_amd64.tar.zst -O https://mirror.keellinux.org/images/debian-13-keel-core_19.0-13_amd64.tar.zst.sha512 -O https://mirror.keellinux.org/images/debian-13-keel-core_19.0-13_amd64.tar.zst.sha512.asc
curl -fLO https://archive.keellinux.org/keel-images-keyring.asc
sqv --keyring keel-images-keyring.asc debian-13-keel-core_19.0-13_amd64.tar.zst.sha512.asc debian-13-keel-core_19.0-13_amd64.tar.zst.sha512
sha512sum -c debian-13-keel-core_19.0-13_amd64.tar.zst.sha512
cp debian-13-keel-core_19.0-13_amd64.tar.zst /var/lib/vz/template/cache/

If sqv prints E71DB9C3CA6AC18075395CC3ED3A709C4F3E2F3C, the signature is good. It also prints "Missing key" for the main key of the project. This is expected.

Make the container

pct create 200 local:vztmpl/debian-13-keel-core_19.0-13_amd64.tar.zst --hostname core \
  --unprivileged 1 --features nesting=1 \
  --net0 name=eth0,bridge=vmbr0,ip6=auto

Start the container and log in on its console as root. The first boot asks its questions there.

Boot the machine from the ISO and install. The first boot of the installed system asks the same questions as the template.

The first boot

The questions of the first boot, of all the modes and roles. A node asks only those of its mode and role (the guides below show each one):

  • Root Password password
  • Installation mode
  • System Notifications
  • Role of this node
  • Invite a node
  • Join a mesh

No password is copied between nodes: only the invite lines (decision 0076).
